# Настройки — инвентаризация

Источник правды для эталона `docs/design/settings.html` (новый раздел; «было» — текущий код T3 Code). Собрано по коду 29 окт 2026.

**Что это за раздел.** Всё, что пользователь Marp настраивает: устройство (тема, шрифты, композер, клавиши), агентов (провайдеры, модели, треды, задачи, браузер, устройства), код (проекты, git, ворктри), машины и доступ к ним, обслуживание. Значения хранятся на этом устройстве, в окружении (машине) или в проекте/checkout; почти всё сохраняется сразу.

**Как читать строку.** `- **ID** что есть в продукте — `файл:строка` ⟶ статус`. Статус: `✓ #экран` (в скобках — что поменяли), `＋ новое: что`, `✗ убрано: почему и как сделать то же самое`. Пути — от `apps/web/src/`, если не указано иное.

Repo: `D:\VSProjects\Marp` (T3 Code fork), branch `design/marp-design-system`. Every path below is relative to `apps/web/src/` unless it says otherwise.

**Autosave model (applies everywhere unless noted).** There is no Save button. Each control writes as soon as it changes, through `useUpdateScopedSettings` (`components/settings/useScopedSettings.ts:100`). Server-scoped keys fan out to every selected environment. Device keys go to client settings. Text and number inputs commit on blur or on commit. Failures show toasts:

- "Setting not saved" (warning, with the reason) — `components/settings/useScopedSettings.ts:56`
- "Setting saved on some environments" / "Setting not saved", with "Could not save on {label}: {msg}" and "Saved on {labels}." — `components/settings/useScopedSettings.ts:85-93`
- A missing scope fails with "This connection lacks permission to change these settings." — `components/settings/useScopedSettings.ts:72`

**Exception:** OpenTelemetry export on the Diagnostics page is an explicit Save/Discard form (DIAG-40..48).

## Observations

**Duplication**

- Diagnostics has two process-resource histories that do almost the same job. "Resource timeline" plus "Live process tree" (native telemetry) sits next to "Live Processes" plus "Resource History" (the server's process diagnostics). Each has its own 5m/15m/30m/1h toggle with different bucket sizes, its own Kill column and its own refresh. The same "Refresh resource history" aria label appears twice on one page.
- "Cleanup" is the title of two different sections: Maintenance (manual run and results) and Worktrees (rules). The Maintenance "Delete now" button also deletes worktrees according to rules configured on another page. Search ids are still `storage-*` after the Storage page was removed.
- The same Wrench icon marks both Maintenance and Diagnostics.
- "Restore device defaults" is near-duplicated by per-row reset buttons. It resets about 60 keys across many pages, yet it lives only on General.
- Settings search exists twice: the sidebar `/` search and the command palette "Settings" group. They share a corpus but use different matchers, so the same query can rank differently.

**Confusing grouping and naming**

- "Restore device defaults" also resets server-scoped, environment-wide keys: provider update checks, continue threads, background activity, git fetch interval, worktree start-from-origin, text generation model. So it is not only device settings, despite the name and the device-only General page.
- Labs mixes device-local toggles (boring sidebar, legacy plan mode) and server-scoped toggles (guest links, linked environments, Simlock) under a scope sentence that suggests everything is per environment.
- About is device-only, but its child page Open source licenses is not. The static licenses page shows "Applying settings for All projects across All environments" and can be blocked by "Reconnect {env} to change its settings."
- Diagnostics shows the multi-environment scope sentence while the content is always one environment. With "All environments" selected it silently uses the primary one.
- Naming drifts between nav and section titles: "Environments" (`/settings/connections`) vs the "Connections" group heading and the Labs link text "Connections"; "Archive" (nav) vs "Archived threads" (page title); "Beta" section inside "Labs"; "SnapShots" vs `snap-shot`.
- At project scope, Maintenance silently drops the "Artifacts and logs" and "Cleanup" sections (returns null) with no notice, while other rows turn inert with a tooltip.
- There is no checkout picker in the scope sentence. Checkout scope is reachable only from notices or the Projects page, so it is hard to discover and hard to leave.
- "Advanced" in the Background activity select is disabled with "(one environment)" and gives no direct way to pick an environment from there.

**Dead ends and one-way doors**

- Archived thread Delete is right-click only and needs the local API. Web users have no delete at all, there is no bulk unarchive or delete, and no way to open an archived thread.
- Open source licenses has no back link, and the breadcrumb "Settings" crumb is not a link.
- Database notice "Dismiss" is stored per environment in localStorage with no way to un-dismiss.
- Telemetry export saves but needs a manual server restart. No restart action is offered ("Saved. Restart the server to apply.").
- No web keybinding opens settings. CmdOrCtrl+, works only through the desktop menu.
- "Two-line folder rows" stays active and editable when the boring sidebar is off.

**Overly technical copy**

- Diagnostics is heavy with jargon: "Native", "Sidecar", "Process scan x/y retained", "Inaccessible", "Instrumented application I/O", "Logical bytes by operation", "Identity: PID + start time", "Parse Errors", "Spans", "Slow Spans", "INT"/"KILL", "SIGKILL…cannot be handled by the process", and "The process is not a child of the T3 Server."
- The Background activity dialog ("subscribed interval fires", "Host power monitor", "Idle host monitor", "Shared policy") and its profile descriptions ("scoped background probes while any subscribed client remains connected") read as engineering notes.
- The Database notice exposes an internal compaction command and process detail ("pauses and restarts the background service").
- The OTLP section assumes telemetry expertise ("OTLP HTTP receiver", "Set by desktop", "Running: … from VAR").
- Inconsistent capitalization: Title Case section titles ("Live Processes", "Trace Diagnostics", "Most Common Failures", "Background Activity" dialog, "Check for Updates", "Up to Date") sit beside sentence case elsewhere ("Resource monitor", "Host & collection", "Artifacts and logs").
- Ellipsis style varies: "..." and "…" are both used ("Loading live processes..." vs "Loading open-source notices…").

**Out of scope but relevant**

- Mobile has its own native settings implementation (`apps/mobile/src/features/settings/*`, `apps/mobile/src/features/diagnostics/SettingsDiagnosticsRouteScreen.tsx`). A web redesign will not carry over automatically.

Пути ниже даны относительно `apps/web/src/`, если не указано иное. Все UI-строки приведены дословно.
Область (scope): `SETTINGS_DEVICE_ONLY_PATHS` (`components/settings/SettingsScopeSentence.tsx:45`) содержит general, appearance, chat, diffs и snap-shot. Keybindings в этот список НЕ входит, поэтому на этой странице есть строка выбора scope.
Сохранение: все контролы сохраняются автоматически сразу при изменении. Исключения отмечены явно: «явное сохранение» у keybindings, у shortcut для SnapShot и в theme editor. Device-настройки являются client settings (`packages/contracts/src/settings.ts:350` `ClientSettingsSchema`), их сохраняет `persistClientSettingsPatch` (`hooks/useSettings.ts:190`). Выбор темы и флаг «Separate fonts» хранятся в localStorage (`hooks/useTheme.ts:41`, `appearanceFonts.ts:20`).

## Observations

- **"Restore device defaults" делает больше, чем обещает.** Кнопка есть только на General, но сбрасывает настройки Appearance, Chat, Diffs, Browser, а также server-scoped настройки страниц Threads и Maintenance (text generation model, background activity, provider update checks, add-project base directory, continue after restarts) через текущую цель scope (`SettingsPanels.tsx:576-644`). Метка "device" неточна, а место для кнопки неочевидное. При этом она НЕ сбрасывает Font smoothing, Thread details, Separate fonts, Plan mode и любые настройки SnapShot.
- **Поиск предлагает "Contrast" и "Glass opacity" дважды.** Search ids с префиксом существуют потому, что id контролов уже заняты (`settingsSearch.ts:301-313`).
- **Строки из Labs дублируют Chat.** "Context window indicator (legacy)" и "Plan mode (legacy)" управляют composer (`SettingsPanels.tsx:695-729`), но находятся в Labs, а не в Chat.
- **Заметная функция спрятана в Advanced.** "Composer context" (поведение composer) лежит в Advanced → Interface раздела Appearance. "Show skills in slash menu" лежит в Chat → Advanced.
- **Word wrap стоит под Typography,** хотя относится к коду/diff. "Diff colors" — на Diffs, а остальные цвета — на Appearance.
- **Связь между страницами не видна из UI.** Описание "Working section" ссылается на Labs ("The boring sidebar in Labs…"). "Diff layout" также меняется из тулбара diff. Thread details также настраиваются правым кликом по карточке.
- **В форке Marp остался бренд T3 Code:** "Open pull requests in T3 Code", "Applies to this device while T3 Code is open.", "Drop T3 Code or VS Code .json files", "T3 Code already uses this for…", "Included with T3 Code…", "Restart T3 Code…".
- **Технический текст.** Конструктор when (Negate, and/or, сырые id команд в tooltip), "Open keybindings.json", "Environment identification" (artwork/pill), Panel animations в ms, Contrast/Glass в %, пороги в описании "Proactive panels" ("at least 3 files or 50 lines").
- **Явное и автоматическое сохранение смешаны.** Почти всё сохраняется автоматически, но keybindings, сочетание SnapShot и theme editor требуют Save/Cancel. В Keybindings "Remove" срабатывает без подтверждения.
- **Keybindings выбиваются из группы.** Страница стоит в device-группе навигации, но это настройка environment (видна строка scope, пишет во все подключённые environments). Из навигации это не видно.
- **Расходится стиль контролов одного типа.** Описание Send shortcut без точки в конце. В опциях "(default)" написано по-разному: "Red & green (default)", "Comfortable (default)", "Word (default)", "Whoosh (Default)", а в Diff layout, Project order, Time format пометки нет. Типы контролов: Thread details — кнопка-меню, Capture sound — меню, а аналогичные выборы сделаны через select.
- **Theme editor живёт отдельно от Settings.** Это плавающая панель вне модального окна Settings, она переживает навигацию. Цветовая схема и темы хранятся в localStorage, а не в client settings, поэтому не синхронизируются как остальные device-настройки.
- **"Separate fonts" меняет набор строк Typography.** Переключатель стоит в Advanced под строками, которыми управляет, и хранится вне client settings.
- **Мастер SnapShot сильно ветвится по платформам** (macOS, Windows, GNOME, KDE, Hyprland, Niri, picker, portal), десятки строк статуса. При редизайне нужно сохранить все ветки.

Base path: `apps/web/src/`. All paths below are relative to `apps/web/src/` unless they start with `packages/`.

How scope works on these pages. Every settings page has a scope picker in the header (machine, project, checkout). It lives in `SettingsScopeContext.tsx` and `settingsScope.ts`, and the search params are `?machine=&project=&checkout=`. `settingsSearch.ts:1157-1179` (`SETTINGS_CATEGORY_SCOPES`) marks all five pages as `null`, meaning their scope is mixed. Scope is decided per row:

- Rows marked `serverScoped` with `settingKeys` write to the selected environment(s) or project overrides through `useUpdateScopedSettings`. They show inheritance and override indicators (`SettingInheritance.tsx`; `settingsLayout.tsx:300-345`), a "Mixed" value when targets disagree, and a reset button when the value differs from the default.
- Browser rows use client settings (`useClientSettings` / `useUpdatePrimarySettings`). They are per device and do not change with the scope picker.
- Providers is per environment and needs one concrete environment. Selecting a project adds per-project enablement overrides.
- Nearly everything saves automatically: a switch or select commits on change, and a text input (`DraftInput`) commits on blur or Enter. The exceptions use an explicit Save, Add or Create button: dialogs, wizards, the custom model editor, ACP agent provider rows, scheduled tasks, and device host editors.

Sidebar group "Agents" contains Providers, Threads, Browser, Devices and Scheduled tasks (`settingsSearch.ts:126-135`). Their icons are Bot, MessagesSquare, Globe, Smartphone and CalendarClock (`SettingsSidebarNav.tsx:96-100`).

## Observations

**Duplication and split homes**

- Idle compaction lives in three places: the global "Compact idle threads" under Providers › Advanced, each Claude instance's "Compact idle threads" select under Runtime, and the help text cross-reference "Providers > Advanced". The Threads page has nothing even though it is a thread behaviour (PROV-50, PROV-85).
- Health check interval is configured on Providers but governed by Maintenance › Background activity. The PolicyTooltip has to explain the split (PROV-84).
- Model settings are spread over four pages. Default and fallback model are on Threads. The text generation model is also on Threads, with an override on Source control. Per-provider model visibility, order and favorites are on Providers. The scheduled-task model is in the task dialog. Each uses a slightly different picker: some include traits, Fallback and Scheduled do not (THR-02, THR-03, THR-15, SCHED-22).
- Sign-in UI comes in three implementations: the Codex managed card, the generic ProviderAuthenticationSection, and Antigravity's setup plus account. They have overlapping but differently worded buttons ("Continue with ChatGPT" / "Sign in", "Disconnect" / "Sign out", "Change account" in both) and different callback-paste copy (PROV-33–46).
- Cursor configuration is split. The API key is under Setup on the card, while the keychain usage toggle sits in a separate Usage providers section and only on macOS (PROV-31, 80, 107).
- "Update all" in the Providers header acts on every connected environment, not the device tab being viewed (PROV-07).
- The CLI "t3 command" row was listed under providers in the brief, but it renders on About (PROV-103).

**Confusing grouping**

- Providers › Advanced holds a single Claude-only row (Compact idle threads) next to the health interval.
- Threads › "New projects" (Add project starts in) is a project-browser setting, not a thread setting.
- Threads › Snooze disappears in project scope and is never explained (THR-06).
- Browser mixes a server-scoped, project-overridable row (Agent access) with per-device client settings, but has no indicator of which rows follow the scope picker.
- Browser › "Browsing" combines profiles, link handling, the floating preview and the search engine. Viewport, zoom and appearance hide under Advanced.
- Devices' hub switch writes to all environments in scope, and device sources write to every connected environment. That differs from most scoped rows, and nothing in the UI says so beyond failure toasts.
- The Providers instance editor is long. On ACP agents it reads Status, Display name, Setup, Runtime, Environment, Native sessions, Agent providers and Models in one scroll, with the Models list capped at max-h-64.

**Dead ends and missing reverse paths**

- No confirmation for: deleting a provider instance (PROV-25), removing a custom model (PROV-72), Codex "Disconnect" (PROV-39, while the generic "Sign out" does confirm), removing a device host (DEV-13), and deleting a scheduled task (SCHED-10).
- Once a Codex instance is in managed mode, Settings offers no way back to "Use existing CLI". That option exists only during onboarding (PROV-101).
- Usage hubs have an `enabled` field and display "· Disabled", but there is no way to toggle it, and editing a hub requires removing and re-adding it (PROV-81, 83).
- ACP native session and agent-provider lists are fetched by hand ("List sessions" / "List providers") and are not live. Agent-provider headers are write-only, with no indication whether any are set.
- Scheduled tasks can't be duplicated. The environment is locked after creation. Permission mode and interaction mode are fixed to defaults and hidden.
- Browser settings on the web are shown as disabled with "Only available in the desktop app.", which gives no path forward for web users.

**Overly technical copy**

- "CODEX_HOME path", "Shadow home path … auth.json", "CLAUDE_CONFIG_DIR path", "Launch arguments … codex app-server", "pi --mode rpc", "ACP source", "Registry agent ID", "Authentication method … ACP authentication method ID", "Executable override … distribution executable", and "Instance ID / Letters, digits, '-', or '_'".
- The provider Environment section uses "VARIABLE_NAME = value" with a lock glyph; the Agent providers editor uses "Write-only headers JSON"; usage hubs refer to "CLIProxyAPI hub" and "Management key".
- Simlock help text cites `AGENT_DEVICE_DAEMON_AUTH_TOKEN`, `AGENT_DEVICE_DAEMON_BASE_URL` and a CLI command. EAS help mentions "extra.eas.projectId" and "EXPO_TOKEN".
- Webhook copy uses "Replay key", "Coalesce key/window", "HMAC-SHA256" and the `{{body.path}}` template syntax inline.
- Status vocabulary drifts: "Not found" vs "Not installed", "Unavailable" vs "Needs attention", "Checked … ago" vs "Refreshing providers", and the Antigravity-only "Installed · Sign-in not checked".

Paths are relative to `apps/web/src/` unless they start with `packages/`. "cs" = `components/settings/`.

Conventions used throughout:

- **Autosave**: every `SettingsRow` control writes as soon as it changes, through `useUpdateScopedSettings` / `useUpdatePrimarySettings`. Text inputs and textareas save on blur. Nothing has a Save button unless an item says "explicit save".
- **Scope**: `serverScoped` rows are environment settings that a project can override. They show a `SettingInheritance` badge and popover ("Mixed across selected environments" / "Overridden for this project" / "Inherited from the repository's t3.json" / "Set on the environment" / "Built-in default"), plus "Reset to inherited value" or "Reset to default" (`cs/settingsLayout.tsx:365-443`). When a row can't be changed, its control is replaced by inert text: "This connection lacks permission to change settings on {env}." / "Reconnect the selected environment to change this setting." / "Environment-wide setting. Select an environment to change it." (`cs/settingsLayout.tsx:395-412`). A failed save shows the toast "Setting not saved", "Could not save on {env}: …" (`hooks/useSettings.ts:598`).
- **Mixed**: with several environments or checkouts selected, values that differ show "Mixed" in selects, pickers and switches.
- **Device-local settings**: `browser*`, `loadBalancing*` and pull request routing are client settings, split out of the patch by `splitPatch` (`hooks/useSettings.ts:608`).
- **Scope per page** (`cs/settingsSearch.ts:1172-1195` `SETTINGS_CATEGORY_SCOPES`): projects=`project`, source-control=`environment-defaults`, worktrees=`project-defaults`, connections/access=`connections` (always available, no scope axis). `/settings/integrations` is a dead route that redirects to `/settings/browser` (`cs/settingsSearch.ts:1199`, `routes/_chat.settings.integrations.tsx:3`).
- **Sidebar groups** (`cs/settingsSearch.ts:108-140`): "Code" = Projects, Source control, Worktrees. "Connections" = Environments (`/settings/connections`), Sharing & access (`/settings/access`). Browser and Devices sit under "Agents".

## Observations

1. **Naming drift.** Routes, nav labels and file names don't match. `/settings/connections` is labelled "Environments" in the nav but its file is `ConnectionsSettings`, the nav group is "Connections", and its sections say "This app" / "Environments". `/settings/access` ("Sharing & access") renders the same component, and its section title is the machine label. `IntegrationsSettings.tsx` holds Browser and Devices, and `/settings/integrations` is a dead redirect. Copy still says "backend" (toasts "Could not add backend", "Backend added", "Could not switch backend on") next to "environment". Linked-env help text points users to "Settings → Connections → Create link", a path that no longer exists ("Create link" is under Sharing & access › Authorized clients) (`cs/LinkedEnvironmentsSettings.tsx:338`).
2. **One page split across two.** Environments and Sharing & access are one component with a `view` prop. The primary machine (version, network, Tailscale, WSL, T3 Connect) appears only on the access page, while other machines' version, update and permissions controls live on Environments. Your own machine therefore isn't in the Environments list at all (except the "This app" local toggle on desktop). "Local environment" (Environments) and "Network access" / "WSL backend" (Access) all restart the local backend but sit on different pages.
3. **Duplicated scope and permission UIs.** "Permissions" is a `<details>` on the access page and an inline toggle per saved env. Both use `SessionPermissions` with slightly different copy. The pairing "Permissions" checklist reuses the same 16 scopes. The ellipsis "Icon" submenu appears on both pages.
4. **Defaults scattered across pages.** `ProjectDefaultsSettings` renders three subsets by `category`: Projects gets Model and Workspace, Source control gets Repositories (auto pull, credits, merge method), and General gets Model, Fallback, Permissions and Workspace. Worktree submodules and worktree cleanup come from `ProjectDefaultsSettings` and `StorageSettings` respectively. The same setting is reachable from 2–3 pages depending on scope, and the Projects page tells users to "hop to any other settings page", which is a sign the project page is incomplete on its own.
5. **Source control page mixes three concerns.** It holds repository behaviour (project-overridable), server tool discovery (env-only, read-only switches that look interactive: "{label} availability" switches are always `disabled`), and AI writing (env-only, partly under Advanced). The writer model, a model setting, hides under "Advanced" while review guides (beta) are top level.
6. **Many one-way doors or missing confirms.** "Revoke others", per-link "Revoke" and per-client "Revoke" have no confirmation. Remove saved env uses the native `requestConfirmDialog`, while the T3 Connect removal uses a styled AlertDialog. Removing a route is native too. Project removal uses `api.dialogs.confirm`. Four confirmation styles.
7. **Overly technical copy.** Examples: "MagicDNS", "Tailscale Serve", "loopback link would dial itself", "Copy MCP URL" with a `claude mcp add` hint, "Copy trace ID", the monospace diagnostics facts table, raw scope ids in the "Granted scopes" popover (`code` font), "{ENV_VAR} and the {cli} login", "redaction markers", "Pairing code" with placeholder "PAIRCODE", "SSH-managed tunnel", and "Client not supported" without a next step on discovered rows.
8. **Dead ends and hidden states.** Load balancing and Pull request sharing vanish below two environments, with no hint they exist. Linked environments only appear on peer-link hosts. T3 Connect rows only appear with cloud config, and the web shows only the revoked notice. Devices "Use devices" is disabled at project scope with no visible reason (only inert). Worktree location silently disappears at project scope or on old servers. Several "Update the selected machines…" notices give no update action.
9. **Device vs environment scope is invisible.** Load balancing, PR sharing, browser settings, the default advertised endpoint and the merge method's "Last selected" are per device, but only PR sharing says so ("This applies only to this device"). Browser rows look identical to the server-scoped "Agent browser access" row above them.
10. **Save model inconsistency.** Most settings autosave, but source control tokens need explicit Save, host settings autosave on change, mixed writing style needs "Apply instructions to all", and branch/instructions textareas save only on blur (no visible saved state). The project name commits on blur or Enter, and an empty name only shows a toast.
11. **Advanced folds hide frequently needed items.** Submodules, settled/unchanged/keep-when cleanup, change-request templates, the writer model and browser viewport/zoom/appearance are folded. A search jump auto-opens them, but browsing does not reveal them.
12. **Remote/relay specifics are spread around.** Relay-only envs get "Add direct route" in diagnosis. Route mode offers "Add T3 Connect". Discovered T3 Connect rows offer "Add route". Routes can be added from the row menu, the routes list and the diagnosis panel: three entry points into the same dialog in route mode.

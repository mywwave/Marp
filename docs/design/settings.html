Эталон · Настройки · 29 окт 2026

Settings

Новые настройки Marp. Раньше: модалка с узкой колонкой, 25 разделов, фраза «Applying settings for … across …» на каждой странице и функции, разбросанные по 2–4 местам. Теперь: полноэкранное рабочее пространство в композиции приложения, страница Overview с тем, что требует внимания, честный бейдж «где хранится», раскладки «список + детали» для провайдеров, машин и проектов. Ничего не потеряно: инвентаризация — 761 пункт, у каждого статус (вкладка Checklist).

Решения

Было → стало → почему.

Рабочее пространство вместо модалки

Было
Модалка 80rem, колонка ~470 px, фон затемнён.
Стало
Настройки занимают окно: навигация на бумаге, лист справа, «Back to app» и Esc.
Почему
Настройки — место, где работают минутами; узкая колонка в огромном окне тратила место. Механика маршрута та же: тред на фоне не перемонтируется.

Overview

Было
/settings открывал General.
Стало
Что требует внимания + сводки агентов, машин, устройства.
Почему
Отвечает на «всё ли работает» без обхода 20 разделов.

Где хранится — в шапке

Было
Фраза «Applying settings for All projects across All environments», скрытая на device-страницах.
Стало
Бейдж «This device» или пилюля «Saved to: …» с проектом, машиной и checkout.
Почему
Пользователь видел одинаковые строки, сохраняемые в разные места (наблюдение «Device vs environment scope is invisible»).

Группы по смыслу

Было
5 групп, две без заголовка, Diffs среди device-настроек, Archive последним.
Стало
You · Agents · Code · Connections · System.
Почему
Заголовок группы отвечает «про что это».

Threads & models

Было
Модели на 4 страницах, сжатие тредов в Providers › Advanced.
Стало
Модели и поведение тредов — одна страница; провайдеры — про аккаунты и рантайм.
Почему
«Какой моделью начнётся тред» ищут в одном месте.

Providers во вкладках

Было
Длинная лента Status → Setup → Runtime → Environment → Sessions → Models.
Стало
Список слева, справа вкладки Account / Runtime / Models / Variables / Sessions.
Почему
У ACP-агентов редактор был длиннее экрана в 3 раза.

Machines

Было
Environments и Sharing & access — один компонент на двух страницах; своей машины в списке нет.
Стало
Одна страница: все машины, включая эту; детали во вкладках Overview / Access / Clients / Permissions.
Почему
Сеть, WSL и локальный бэкенд перезапускают одно и то же, а лежали на разных страницах.

Git & pull requests

Было
Source control и Diffs & pull requests отдельно.
Стало
Одна страница: Repositories, Pull requests, Diffs, Writing, Tools & hosts.
Почему
Это один рабочий процесс; старые адреса редиректят.

Единые подтверждения

Было
4 стиля подтверждений, у 7 удалений и отзывов — никакого.
Стало
Одно окно подтверждения: что пропадёт, кнопка-действие.
Почему
Отзыв доступа и удаление инстанса нельзя отменить.

Нужно от сервера

1. Удаление архивного треда из веба (сейчас только через local API desktop) — RPC удаления треда. needs server
2. Сводка Overview «обновления провайдеров на всех машинах» уже есть по машинам; агрегат по всем — собрать на клиенте, сервер не нужен.
3. Остальное — клиент: маршруты, раскладки, подтверждения, команда settings.open.

Открытые вопросы

1. «Restore defaults» сбрасывает и значения окружения (provider update checks, background activity…). Оставить так, но честно показать в окне, или ограничить только устройством?
2. Labs: оставить отдельной страницей или раздать флаги по разделам с меткой «Beta»?
3. Diagnostics: два похожих блока истории процессов — объединить в один (предлагаю) или оставить оба?

Тред — место, где пользователь ставит задачу, видит работу без шума, решает, когда его спрашивают, проверяет результат и отправляет его. Это живой прототип: отправьте сообщение — «агент» пойдёт по шагам; остановите, направьте, поставьте в очередь, одобрите, ответьте, откатите, откройте дифф и оставьте комментарий к строке. Под прототипом — спецификация каждого взаимодействия. Прошлая версия — archive/thread-2026-10-29.html, инвентаризация — 732 пункта (Checklist внизу).

Как устроено

Шесть решений, из которых следует всё остальное.

1. Ход = вопрос → работа → ответ → чекпоинт

Было
Лента из отдельных сообщений, шагов, уведомлений; откат только через «Edit from here».
Стало
Каждый ход — одна единица: сообщение, свёрнутый журнал работы с длительностью, ответ, разделитель «Checkpoint · N files changed · View diff · Restore».
Почему
Пользователь думает ходами: «что я попросил — что изменилось — можно ли вернуть».

2. Работу видно, но она не шумит

Было
Все шаги сразу, шиммер на Thinking, тикающие таймеры в нескольких местах.
Стало
Во время работы журнал раскрыт и показывает последние 3 шага + «N earlier steps»; после хода сворачивается в одну строку-сводку. Тикают только таймер хода и живого шага.
Почему
Следить за агентом нужно, читать каждую строку — нет.

3. Решения — карточкой над композером

Было
Одобрение в ленте, вопрос и «Implement» — в композере, легко пропустить при прокрутке.
Стало
Одобрение, вопрос, план, ошибка — карточка, прилипшая к низу ленты над композером; клавиши на кнопках. После решения — строка-след в журнале («Approved rm -rf dist»).
Почему
Решение должно быть там, куда смотрит пользователь, и оставлять след.

4. Композер знает, что сейчас будет

Было
Кнопка отправки с девятью состояниями, причина «нельзя» — только в тултипе.
Стало
Плейсхолдер и кнопка говорят, что произойдёт: Send / Steer / Stop; подсказка «Enter steers · Ctrl+Enter queues»; очередь — видимые строки с удалением; причина блокировки — строка с действием.
Почему
Никаких сюрпризов от Enter.

5. Шапка — для ежедневных действий

Было
Git, ветка и Open in — в карточке деталей, которая прятала их на невысоком окне.
Стало
Название (клик — переименовать), статус с временем, ветка, +N −M → дифф, Open in, Git (умная подпись; если нельзя — почему), детали, терминал, панель.
Почему
Коммит и PR — каждый день; они не зависят от высоты окна.

6. Дифф говорит с агентом

Было
Комментарий к строке уходил в черновик незаметно.
Стало
«+» у строки → поле → «Add to prompt» → чип в композере «session.ts:43 · …». Клик по шагу «Edited …» открывает дифф на этом файле.
Почему
Ревью и следующая инструкция — один жест.

Спецификация взаимодействий

Элемент → действие → результат → что видно → как отменить. Всё проверяется в прототипе выше.

Решения и вопросы

Нужно от сервера

1. Stop процесса в терминале (SIGINT) — проверить RPC сигнала для терминальных сессий. needs server
2. «N files changed» у чекпоинта и Restore — из существующего диффа хода и revert; новый RPC не нужен.
3. Steer во время хода — уже поддерживается (followUpBehavior); очередь — существующая queue.

Открытые вопросы

1. Журнал во время работы — последние 3 шага (сейчас) или всё?
2. Карточка решения прилипает к низу ленты (сейчас) или живёт в потоке?
3. Детали треда — меню по кнопке (сейчас) или боковая карточка как раньше?

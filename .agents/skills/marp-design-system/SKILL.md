# Marp Design System

Эталон — **`docs/design/reference.html`**. Это единственный источник правды по виду. Если правило здесь и эталон расходятся, прав эталон: откройте его и повторите 1 в 1. Перед работой откройте эталон в браузере (`python -m http.server 8765` в `docs/design/`) и найдите ближайший образец.

Справочники в этой папке:

- `references/tokens.md` — все токены со значениями для светлой и тёмной темы и куда их ставить.
- `references/components.md` — рецепты примитивов: размеры, состояния, разметка.
- `references/product.md` — рецепты продукта: шелл, сайдбар, тред, сообщения, вызовы инструментов, композер, дифф, терминал, палитра команд, настройки.
- `references/patterns.md` — экраны, статусы агента, пустые состояния, загрузка, ошибки, длинные списки.
- `references/copy.md` — как писать тексты интерфейса (английский), подсказки, ошибки, кнопки.
- `references/checklist.md` — чек-лист перед сдачей. Пройдите его целиком.

Эталоны разделов (тред, сайдбар, настройки…) лежат рядом в `docs/design/*.html`; как их делать — скилл `design-reference`.

## Для кого и какой характер

Пользователи — разработчики, которые весь день гоняют кодинг-агентов (Codex, Claude, Cursor, Grok, OpenCode, Antigravity) на своей машине, на удалённом сервере и с телефона. Они смотрят в Marp часами. Интерфейс **тёплый, воздушный, спокойный и честный**: тёплая бумага вместо холодного серого, воздух вместо рамок, текст и код читаются без усилия, а статус агента виден всегда и никогда не врёт. Каждый экран отвечает на три вопроса: что сейчас происходит, нужен ли я, что делать дальше.

Язык интерфейса — английский (как в продукте). Документация дизайн-системы и эталонов — на русском.

## Семь законов (нарушать нельзя)

1. **Воздух вместо рамок.** Поверхности разделяются фоном (`bg` → `surface` → `surface-2`) и отступами. Рабочая область — «лист» `surface` радиус 20 на тёплом `bg`, без рамки, с `shadow-card`. Никаких `border` вокруг карточек, полей, кнопок, сообщений и блоков кода. Единственная линия — `line` (1px) между строками списка/таблицы и в разделителях меню.
2. **Один акцент.** Акцент (`primary`; по умолчанию «Глина», пользователь выбирает другой в Settings → Appearance) = главное действие или «выбрано». В коде только роли `primary*`, никогда конкретный оттенок. На экране ровно одна primary-кнопка (в треде это «Send» композера). Акцент не используют для декора, заголовков, ссылок в тексте и статусов агента.
3. **Статус честный и всегда виден.** У агента пять состояний — `working`, `needs-you`, `done`, `failed`, `idle` — с фиксированными цветом, иконкой и словом (`references/patterns.md` «Статусы агента»). Статус показан там, где на него смотрят: строка треда в сайдбаре, шапка треда, композер. Спиннер только пока реально идёт работа; «Working» без живого процесса — баг. Время работы — числом («Working · 2m 14s»).
4. **Пустота подсказывает — коротко.** Пять типов («ещё ничего нет», «нужно подключить» — плитка `accent-soft`; «ничего не нашли», «ещё не пришло» — серая; «всё сделано» — зелёная) в четырёх размерах (страница, карточка, строка, панель). Заголовок до 5 слов, одно предложение до 12 слов, одна кнопка или ни одной. Ошибка и нет права — не пустота.
5. **Код и числа читаются.** Код, пути, команды, ветки, хэши, клавиши — только `font-mono`. Текст ответа агента — 15/24, а не 13: его читают абзацами. Длинные пути — обрезка посередине (`MiddleTruncate`), имя файла видно всегда. `tabular-nums` — только в колонках, таймерах и счётчиках, которые меняются на глазах. Числа и время — через общие форматтеры, не руками.
6. **Одна шкала.** Размеры, отступы, радиусы, цвета, длительности — только из токенов. Никаких «на глаз» `13.5px`, `#333`, `mt-[7px]`. Нет нужного токена — остановитесь и спросите, не изобретайте.
7. **Спокойное движение.** Цвет/фон — 150 мс, появление и сдвиг — 220 мс `cubic-bezier(.22,1,.36,1)`, переключатель — пружина `cubic-bezier(.3,1.12,.4,1)`. Нажатие кнопки — `scale(.97)`. **Ничего не перерисовывается бесконечно**: ни шиммеров на стримящемся тексте, ни пульсаций, ни крутящихся градиентов — они грузят GPU на 120 Гц экранах. Единственное исключение — спиннер 14px, пока идёт работа. Всё отключается при `prefers-reduced-motion`.

## Как строить компонент (порядок действий)

1. Найдите образец в эталоне. Если он есть — повторите разметку, токены и состояния 1 в 1.
2. Если образца нет — соберите из существующих примитивов (`apps/web/src/components/ui/*`). Новый примитив — только с согласия пользователя, и он сразу добавляется в эталон.
3. Опишите все состояния: default, hover, focus-visible, active, disabled, loading, empty, error. Состояния без образца в эталоне — не выдумывать, спросить.
4. Тексты — по `references/copy.md`: коротко, без жаргона, кнопка называет действие.
5. Проверьте обе темы и два акцента (Глина + Лес). Тёмная тема — не инверсия: свои значения (`references/tokens.md`).
6. Проверьте все поверхности из `AGENTS.md` «Hit every surface» (web, desktop, точки входа, провайдеры).
7. Пройдите `references/checklist.md`.

## Код (React 19 + Vite + Tailwind v4 + Base UI/shadcn)

- Токены — в `apps/web/src/index.css` (слои: примитивы → роли по темам → акценты → геометрия → мост `@theme` в Tailwind). Словарь «эталон → утилита» — `references/tokens.md`. В компонентах только утилиты токенов: никаких hex, `style={{}}` с цветами, произвольных `[…]`-значений, рамок на поверхностях.
- Примитивы — `apps/web/src/components/ui/*`. Они владеют своим видом: выбирайте `variant` / `size`, не перекрашивайте `className` (`shadcn/no-restyle` роняет линт). Нет нужного вида и он общий — добавьте вариант в примитив; вид одной фичи — в компоненте фичи.
- Иконки — `lucide-react`, stroke 1.75, размеры из таблицы. Логотипы провайдеров — `components/Icons.tsx`.
- Общие для веба и мобилки форматтеры и логика — `packages/client-runtime`.
- Движение без бесконечных анимаций; React-эффекты — только для синхронизации с внешним миром (правило `t3code/no-unreasoned-state-sync`).

## Красные флаги — остановиться и переделать

- Рамка вокруг карточки, поля, кнопки, сообщения или блока кода.
- Две primary-кнопки на экране, текст цвета акцента «для красоты», статус агента цветом акцента.
- Конкретный оттенок акцента в компоненте (`--clay-*`, hex) вместо `primary*`.
- «Working», спиннер или «Thinking…» без живого процесса; статус, который не совпадает с реальным состоянием сессии.
- Бесконечная анимация: шиммер, пульс, бегущий градиент, анимированный бордер.
- Код, путь, команда или ветка не моноширинным шрифтом; путь, обрезанный с конца так, что не видно имени файла.
- Текст ответа агента мельче 15px или шире 760px.
- «No data», «Error», «OK», «Submit», «Something went wrong» в интерфейсе.
- Пустое состояние с двумя кнопками, абзацем текста или акцентной плиткой у «ничего не нашли».
- Значение не из токенов: произвольный hex, `text-[13.5px]`, `rounded-[10px]`, `gap-[18px]`.
- КАПС в заголовках, шапках таблиц и подписях групп.
- Компонент проверен только в одной теме или с одним акцентом.
- Список, который растёт вниз без предела (треды проекта, вызовы инструментов, файлы диффа) без поиска, сворачивания или виртуализации.

## Отговорки и ответы

| Отговорка                                       | Ответ                                                                           |
| ----------------------------------------------- | ------------------------------------------------------------------------------- |
| «Тут рамка нужна для разделения»                | Разделите фоном `surface-2` или отступом. Рамок нет.                            |
| «Разработчикам нужна плотность»                 | Плотность — через иерархию и сворачивание, а не через 11px и рамки. Шкала одна. |
| «Это внутренний/дев-экран»                      | Правила одни для всех экранов.                                                  |
| «Нужного токена нет, поставлю похожее значение» | Спросите. Новый токен добавляется в эталон, потом в код.                        |
| «Быстрее сделать свой компонент»                | Соберите из примитивов `components/ui`. Дубликаты запрещены.                    |
| «Шиммер показывает, что агент думает»           | Статус «Working · 12s» со спиннером 14px говорит то же без нагрузки на GPU.     |
